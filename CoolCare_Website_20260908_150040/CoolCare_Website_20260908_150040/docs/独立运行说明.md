# 运行解压出来的源码

## 只在你现在这台电脑演示

最简单的方法是使用包根目录的 `01_启动现有网页.cmd`，继续运行原来的已配置项目。`web/` 用来展示源码，不需要额外安装依赖。

## 希望运行桌面解压出来的这一份源码

1. 先停止原项目的网页运行窗口，避免两个项目同时占用 3000、3001 端口。不要停止或删除 MySQL。
2. 在解压后的 `web` 文件夹中打开终端，运行 `npm ci`。首次安装需要联网；已有电脑已安装 Node.js。
3. 仅在你自己的电脑上，从原项目 `inventory-web` 文件夹复制 `.env.local` 到解压后的 `web` 文件夹。不要改名成 `.env.local.txt`，也不要把这个文件发给组长。
4. 双击解压后 `web/start-local.cmd`，再打开 <http://localhost:3000/admin/inventory>。

这样会继续连接本机同一个 MySQL 数据库，因此原来的数据还在。**不需要重新执行 schema.sql 或 seed.sql。** ZIP 本身不含密码；复制连接文件是你在自己的电脑上的本地操作。

## 换电脑或交给组员运行

1. 安装 Node.js 22.13+ 和 MySQL 8.4。
2. 先确认 MySQL 中是否已有 `coolcare_service_app` 数据库；已有同名数据库时，不要直接导入覆盖。
3. 只有在全新的演示数据库环境下，才在 MySQL 客户端依次执行包内 `database/schema.sql` 和 `database/seed.sql` 的 SOURCE 命令。
4. 在 `web` 目录运行 `npm ci`，然后运行 `npm run setup`。该命令为新电脑生成自己的本机配置和辅助表设置 SQL，不会自动获取 root 密码。
5. 在已登录的 MySQL 客户端执行 setup 命令输出的 `SOURCE .../setup-mysql.sql;`。
6. 回到 `web` 运行 `npm start`，浏览器打开本机网址。

组员电脑上的 localhost 是组员自己的电脑，不会连接到你的电脑。库存 JSON 快照只作记录参考，不要把它当作 SQL 直接导入。

## 启动故障

- 网页打不开：确认运行窗口没有关闭，等待启动完成。
- 数据库连接失败：Win + R 输入 `services.msc`，检查 `MySQL84` 服务是否运行。
- 端口已占用：关闭之前启动的 CoolCare 运行窗口，避免同时启动两份。
- npm 无法识别：确认安装 Node.js 后重新打开终端。
- 网页登录使用演示账号，不是 MySQL root 账号。

## 验证命令

在 `web` 目录运行：`npm test`、`npm run test:db`、`npx tsc --noEmit`、`npm run build`。

网页在此前的完成检查中通过构建、类型检查、7 项自动测试及路由响应检查。测试临时数据会回滚。未做逐页浏览器点击验收；展示前建议自己走一遍流程。
